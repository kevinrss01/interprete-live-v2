# Mac setup onboarding plan

**Goal:** Guide installed-app users through the microphone, system audio, Meet mute synchronization and virtual microphone requirements before their first meeting.

**Design:** Reuse the onboarding shell and a compact list of four actionable setup rows. Keep the existing voice/account journey, provide a conversation-only deferral, and expose setup again in Settings. Browser onboarding stays unchanged.

- [x] Add read-only native microphone/accessibility/driver status and explicit microphone, audio-prompt, virtual-microphone and installer actions. Download only the official pinned BlackHole package, verify SHA-256 and hand off installation to macOS Installer. No Homebrew, administrator shell command, bundled driver, automatic reboot or permission grant.
- [x] Add typed device-local setup state, feature-specific meeting checks, cancellable polling and completion persistence. System-audio user confirmation and observed signal are separate states.
- [x] Add the setup screen to native onboarding, returning users, Settings and blocked meeting starts. Refresh after returning from System Settings or Installer. Explain restart-required, denied, checking, confirmed and ready states.
- [x] Verify the state model and cancellation with meaningful tests; run app and native checks, inspect synthetic desktop/compact UI and update existing architecture/validation guides. Do not trigger real recording, permission grants or installation during automated verification.

Work locally on the existing task branch and preserve the call-audio fixes and unrelated edits. No publication is requested.
